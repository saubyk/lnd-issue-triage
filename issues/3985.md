## Summary
Feature request (Feb 2020, lnd ~v0.9): a push notification for `synced_to_chain`
so apps do not have to poll `GetInfo` at startup. lnd v0.13.0 added the
streaming `SubscribeState` RPC, and `SERVER_ACTIVE` is only emitted after lnd
has finished waiting for the chain backend to sync, which covers the startup
use case in the report.

## Evidence
- PR #5005 "[RPC] SubscribeState RPC for getting unlocking state of wallet and
  RPC", merged 2021-03-18. First commit `9ef556624` (lnrpc: add StateService)
  is contained in tag `v0.13.0-beta`.
- `lnrpc/stateservice.proto` states: NON_EXISTING, LOCKED, UNLOCKED,
  RPC_ACTIVE, SERVER_ACTIVE, WAITING_TO_START. `SubscribeState` streams
  transitions; `GetState` returns the current one.
- Ordering on current master `lnd.go`: `SetRPCActive()` at :749, the
  "Waiting for chain backend to finish sync" loop at :764, then
  `SetServerActive()` at :855. So a `SERVER_ACTIVE` event implies the initial
  chain sync completed.
- Residual gap: `synced_to_chain` in `GetInfo` is still computed on the fly
  (`rpcserver.go:2096` calls `Wallet.IsSynced()`), so if the backend falls
  behind *after* startup there is still no push event for the flip back to
  false. The report's linked use case (mobile app waiting at startup) does not
  need that; hsjoberg's comment touches on it. This is why confidence is
  medium rather than high.
- No cross-referenced PRs on the issue; no newer duplicate issue found for
  "synced_to_chain subscribe".

## Draft comment
Closing this, because lnd has had a way to do this since v0.13.0 (PR #5005).
The `SubscribeState` RPC streams lnd's startup state, and the `SERVER_ACTIVE`
state is only sent once lnd has finished syncing to the chain. Apps can wait
for that event instead of polling `GetInfo` for `synced_to_chain`. If you need
a notification for the node falling out of sync later, after startup, please
open a new issue describing that case.
