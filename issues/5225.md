## Summary
After bumping an unconfirmed transaction with BumpFee, WalletBalance
(total_balance and unconfirmed_balance) counts the outputs of every replaced
version as well as the live one, so each bump inflates the balance by the
transaction amount until one version confirms. Reported on 0.11, confirmed by
others on 0.14 (#5225, #6677) and 2023 (Voltage on #5244). Reproduced
deterministically on current master with an itest: 6.00 BTC baseline reads
7.00 BTC after one replacement and 8.00 BTC after two, then drops back to
5.9998 BTC once the last replacement confirms. The sibling issue #5244 was
closed in March 2025 citing #9609, but that PR fixed a different listunspent
race and does not touch this; #5225 is the canonical open tracker.

## Evidence
- Root cause is in btcwallet, unchanged since 2018/2019:
  - `wtxmgr/unconfirmed.go:16-60` `insertMemPoolTx`: inserting an unmined tx
    that double-spends an existing unmined tx does not remove the old one.
    Both stay in the unmined bucket. `removeDoubleSpends` only runs from
    `insertMinedTx` (`wtxmgr/tx.go:490-497`), i.e. once a version confirms.
    Roasbeef's 2021 comment describes exactly this ("keeps around all the
    copies until one of them confirms").
  - `wtxmgr/tx.go:1080-1215` `Balance(minConf=0)`: adds every unmined
    credit whose outpoint is not spent by another unmined tx. A replaced tx's
    outputs are unspent, so they are counted alongside the replacement's.
  - Module in use: `github.com/btcsuite/btcwallet/wtxmgr
    v1.6.1-0.20260903142755` (`go.mod:23`). Commit history of
    `wtxmgr/unconfirmed.go` on GitHub shows no relevant change after 2021.
- lnd side does not compensate:
  - `rpcserver.go` WalletBalance is `ConfirmedBalance(0)` for total and
    `ConfirmedBalance(1)` for confirmed; unconfirmed is the difference.
  - The fee bumper's replacement handler
    `sweep/sweeper.go:1727-1771` `handleBumpEventTxReplaced` only cancels
    rebroadcast of the old tx and updates the sweeper's own store. It never
    calls `Wallet.RemoveDescendants`. That call exists but is only used from
    `removeConflictSweepDescendants` (`sweep/sweeper.go:573-640`), which
    runs when an input is seen spent on chain, and from the manual
    `walletrpc.RemoveTransaction` endpoint (#7800, v0.18).
- Related issues: #6677 (2022) closed as duplicate pointing here; #5244
  closed 2025-03-21 by yyforyongyu "should be fixed by #9609", but #9609
  ("Fix inaccurate listunspent result", v0.19) addresses async filter
  registration and an oversized db tx, not unmined double-spend accounting.
  btcwallet#801 (double-spend removal for spends to non-wallet addresses)
  was closed for inactivity 2024-04-08. #9995 (open, 2025) is a different
  case (remote commitment replacing a coop close).
- Workaround available since v0.18: `lncli wallet removetx <txid>` on the
  superseded version.

package itest

import (
	"github.com/btcsuite/btcd/btcutil/v2"
	"github.com/btcsuite/btcd/wire/v2"
	"github.com/lightningnetwork/lnd/lnrpc"
	"github.com/lightningnetwork/lnd/lnrpc/walletrpc"
	"github.com/lightningnetwork/lnd/lntest"
	"github.com/stretchr/testify/require"
)

// testIssue5225RbfWalletBalance reproduces lightningnetwork/lnd#5225: after
// replacing an unconfirmed transaction via BumpFee, WalletBalance keeps
// counting the outputs of the superseded versions.
func testIssue5225RbfWalletBalance(ht *lntest.HarnessTest) {
	if ht.IsNeutrinoBackend() {
		ht.Skipf("skipping for neutrino backend")
	}

	alice := ht.NewNodeWithCoins("Alice", nil)
	ht.FundCoins(btcutil.SatoshiPerBitcoin, alice)

	base := alice.RPC.WalletBalance()
	require.Zero(ht, base.UnconfirmedBalance)
	ht.Logf("issue5225: baseline total=%d confirmed=%d",
		base.TotalBalance, base.ConfirmedBalance)

	// Alice sends a coin to herself; the tx stays unconfirmed.
	tx := ht.SendCoins(alice, alice, btcutil.SatoshiPerBitcoin)
	txid := tx.TxHash()
	op := &lnrpc.OutPoint{TxidBytes: txid[:], OutputIndex: 0}

	afterSend := alice.RPC.WalletBalance()
	ht.Logf("issue5225: after self-send total=%d confirmed=%d "+
		"unconfirmed=%d", afterSend.TotalBalance,
		afterSend.ConfirmedBalance, afterSend.UnconfirmedBalance)

	// findSweep returns the mempool tx that is not the parent.
	findSweep := func() *wire.MsgTx {
		txns := ht.GetNumTxsFromMempool(2)
		if txns[0].TxHash() == txid {
			return txns[1]
		}
		return txns[0]
	}

	// Bump 1: CPFP sweep of output 0.
	alice.RPC.BumpFee(&walletrpc.BumpFeeRequest{
		Outpoint: op, Immediate: true,
	})
	ht.AssertNumPendingSweeps(alice, 1)
	sweep1 := findSweep()
	b1 := alice.RPC.WalletBalance()
	ht.Logf("issue5225: after bump 1 (sweep %v) total=%d unconfirmed=%d",
		sweep1.TxHash(), b1.TotalBalance, b1.UnconfirmedBalance)

	// Bump 2: RBF the sweep at a higher fee rate.
	alice.RPC.BumpFee(&walletrpc.BumpFeeRequest{
		Outpoint: op, Immediate: true, SatPerVbyte: 50,
	})
	ht.AssertTxNotInMempool(sweep1.TxHash())
	sweep2 := findSweep()
	require.NotEqual(ht, sweep1.TxHash(), sweep2.TxHash())
	b2 := alice.RPC.WalletBalance()
	ht.Logf("issue5225: after bump 2 (sweep %v) total=%d unconfirmed=%d",
		sweep2.TxHash(), b2.TotalBalance, b2.UnconfirmedBalance)

	// Bump 3: RBF again.
	alice.RPC.BumpFee(&walletrpc.BumpFeeRequest{
		Outpoint: op, Immediate: true, SatPerVbyte: 100,
	})
	ht.AssertTxNotInMempool(sweep2.TxHash())
	sweep3 := findSweep()
	require.NotEqual(ht, sweep2.TxHash(), sweep3.TxHash())
	b3 := alice.RPC.WalletBalance()
	ht.Logf("issue5225: after bump 3 (sweep %v) total=%d unconfirmed=%d",
		sweep3.TxHash(), b3.TotalBalance, b3.UnconfirmedBalance)

	// Confirm the latest replacement and observe the balance settle.
	ht.MineBlocksAndAssertNumTxes(1, 2)
	final := alice.RPC.WalletBalance()
	ht.Logf("issue5225: after confirmation total=%d confirmed=%d "+
		"unconfirmed=%d", final.TotalBalance, final.ConfirmedBalance,
		final.UnconfirmedBalance)

	// Nothing external came in, so no snapshot may exceed the baseline.
	require.LessOrEqual(ht, b2.TotalBalance, base.TotalBalance,
		"total balance inflated after first replacement")
	require.LessOrEqual(ht, b3.TotalBalance, base.TotalBalance,
		"total balance inflated after second replacement")
}

## Recommendation
Keep open; it is real, easy to reproduce, and affects operators who bump
fees during spikes. Two possible fixes, either would do:
1. lnd: in `handleBumpEventTxReplaced`, call `Wallet.RemoveDescendants`
   on the replaced tx (the wallet already has the API and the sweeper
   already owns both versions). Narrow, covers the BumpFee path only.
2. btcwallet: have `insertMemPoolTx` remove conflicting unmined txs, or
   make `Balance(0)` skip unmined credits whose inputs are also spent by a
   newer unmined tx. Covers every RBF source, including external PSBT bumps.
Also worth a note on #5244 that #9609 did not fix it, so nobody treats that
close as evidence.
