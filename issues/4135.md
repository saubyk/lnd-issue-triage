## Summary
On lnd 0.9.0 a REST `GET /v1/invoice/<hash>` on a node with zero invoices
returned HTTP 500 with "there are no existing invoices" instead of 404. Fixed by
#10064 (ellemouton, merged 2025-07-14, released in v0.20.0-beta): `LookupInvoice`
now maps both "invoice not found" and "no invoices created" to gRPC `NotFound`,
which the REST gateway renders as 404.

## Evidence
- Master `rpcserver.go:5944-5952` (`LookupInvoice`):
  ```go
  case errors.Is(err, invoices.ErrInvoiceNotFound) ||
      errors.Is(err, invoices.ErrNoInvoicesCreated):
      return nil, status.Error(codes.NotFound, err.Error())
  ```
  grpc-gateway maps `codes.NotFound` to HTTP 404. Before the fix the error was
  returned raw, which gRPC treats as `Unknown` (code 2, the value in the
  reporter's JSON) and the gateway renders as 500.
- Fix PR: #10064 "rpcserver: return consistent grpc NotFound error for
  GetChaninfo & LookupInvoice", merged 2025-07-14 (replaces #9810).
- Release note: `docs/release-notes/release-notes-0.20.0.md:207` cites #10064.
- Tag bisect via raw.githubusercontent.com: `rpcserver.go` contains no
  `ErrNoInvoicesCreated` handling in v0.9.0 through v0.19.3-beta; present from
  v0.20.0-beta. Current release is v0.21.3-beta (2026-09-02).
- The `invoicesrpc.LookupInvoiceV2` endpoint already mapped `ErrInvoiceNotFound`
  to `NotFound` (`lnrpc/invoicesrpc/invoices_server.go:456-458`).
- No cross-references on the issue. wpaulino's 2020 pointer to #2332 (missing
  macaroon returns wrong HTTP code) is a different code path; that issue was
  closed in 2023 pending a PR that never arrived.

## Draft comment
Closing this, because it was fixed in lnd v0.20.0 by #10064. Looking up an invoice that does not exist now returns a "not found" error over gRPC, which the REST API reports as HTTP 404 instead of 500. This applies whether the node has other invoices or none at all. If you still see a 500 for a missing invoice on v0.20 or later, please reopen with the request and response.
