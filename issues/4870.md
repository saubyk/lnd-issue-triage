## Summary
Bug report (Dec 2020, lnd v0.11.0, neutrino backend) from Overtorment
(BlueWallet): after a transient failure to fetch a block from Bitcoin peers,
the node's neutrino rescan dies and every later wallet operation that touches
it (e.g. `newaddress`) fails with "Rescan is already done and cannot be
updated" until lnd is restarted. halseth diagnosed it in-thread: the rescan
should retry or wait for new peers instead of exiting. Confirmed still present
on current master by code reading, and kaloudis (ZEUS) reported in Dec 2024
that they "see this fairly often" on neutrino nodes. The gap is real; the fix
belongs in neutrino (restartable rescan) or lnd's neutrino notifier
(restart on error). No PR has ever targeted it.

## Evidence
- lnd master pins `github.com/lightninglabs/neutrino v0.18.0` (go.mod).
- Mechanism, neutrino v0.18.0 `rescan.go`:
  - `Rescan.Start()` (:1391) runs the rescan loop once in a goroutine. On
    any error it closes `r.running`, stores the error in `r.err`, and exits.
    Nothing restarts it.
  - `extractBlockMatches` (:994) calls `chain.GetBlock`; on error it returns
    the error up, which ends the loop.
  - `Rescan.Update()` (:1470) selects on `r.running`; once closed it returns
    `"Rescan is already done and cannot be updated. It returned error: <err>"`.
    That is the exact string in the report.
- `GetBlock` failure string, neutrino `query.go:938`: `couldn't retrieve
  block %s from network`. Now lowercased, otherwise unchanged. Since PR
  lightninglabs/neutrino#273 (2023) the fetch goes through the query
  dispatcher with `QueryNumRetries = 8`, which makes the trigger rarer but
  still exits the rescan when all retries fail.
- lnd side, `chainntnfs/neutrinonotify/neutrino.go:563`: on `rescanErr` it
  only logs `Error during rescan: %v` and keeps running with a dead rescan.
- Symptom recurrence: losh11 (Jun 2022) and kaloudis of ZEUS (Dec 2024)
  report the same error on later versions.
- No merged PR in lnd, btcwallet, or neutrino references this issue or the
  error string. Merged neutrino PRs touching rescan (#175, #273, #275, #300)
  improve fetch robustness but none makes the rescan restartable.
- Reproduction not attempted: the failure path is fully visible in code and
  a unit test would need a fake chain source that fails `GetBlock`, which
  would only restate the reading above.

## Note for the human
Keep open. Worth doing while here: the title is the raw error string; a
clearer title would be "neutrino: rescan exits permanently after a block
fetch failure; wallet ops fail until restart". The `P2` label and `bug` still
fit. The fix is small in shape (make the rescan goroutine restartable, or
have lnd's neutrino notifier recreate it on error) but sits in the neutrino
repo, so it may want a linked issue there.
