## Summary
Process request (Nov 2021, naveensrinivasan, part of the same OpenSSF-style
batch as #5889 and #5966): lnd should adopt a written, ideally machine-enforced
policy for external Go dependencies, with Dependabot for updates, OpenSSF
Scorecard for dependency health, and CVE tracking. There's no lnd-specific bug,
and the thread is two comments from 2021. Since then, the one concrete,
checkable part (known CVEs in the versions lnd ships) has been addressed. A
`govulncheck` scan of the release binaries has run in CI since May 2026, and
Roasbeef opened #11361 to make its findings block merges. Dependabot, Scorecard
and a written admission policy were never adopted. Dependency bumps are manual,
reviewed `build:` PRs. Whether to go further than that is a maintainer call.
Recommend closing as not planned and pointing to the vulnerability scan and
#11361.

## Evidence
- Thread: Roasbeef (MEMBER, 2021-11-09) linked vendoring PR #4582 and suggested
  it for 0.15. The reporter replied that vendoring alone doesn't address the
  issue. Nothing since.
- #4582 "build: start to commit entire vendor directory" is still open and
  unmerged (2020). `lnd/` has no `vendor/` directory on master `c03d36598`.
- The two earlier, narrower issues from the same reporter were closed on
  2026-02-21 as duplicates of this one: #5774 (block dependencies with known
  vulnerabilities; Roasbeef in 2021: "perhaps we should add this to our CI
  pipeline?") and #5740 (Dependabot).
- Vulnerability scanning now exists: `.github/workflows/govulncheck.yml` on
  master. It was added by ziggie in commit 2d1e05acd ("ci: add govulncheck
  binary scan", 2026-05-25) via PR #10838. It runs
  `govulncheck@v1.3.0` against the binaries built by `make release-install`
  on a weekly schedule, on PRs and master pushes that touch Go code or
  `go.mod`/`go.sum`, and in the merge queue. Exit code 3 (findings) is
  advisory for now (warning plus job summary).
- #11361 (Roasbeef, open, 2026-10-19) "ci: make govulncheck findings
  blocking": a test run found 13 reachable vulnerabilities (stdlib and
  `GO-2026-6443` in grpc). The plan is to clear the baseline first, then make
  findings fail CI.
- No Dependabot: there's no `.github/dependabot.yml`. No Scorecard workflow.
  `docs/code_contribution_guidelines.md` only mentions "proper handling of Go
  module dependencies and submodules" and has no admission criteria.
- Dependency updates go through maintainer PRs, e.g. #10841 "build: bump grpc
  to v1.79.3", #10879 "build: bump pgx to v5.9.2", plus Go toolchain bumps
  every month or two (#10875, #11200, #11383). Versions are pinned through
  `go.sum`.
