## Summary
Tracking issue (Oct 2017, halseth) with two tasks. When a channel's funding
transaction never confirms, the responder forgets the channel after 288
blocks, but the funder can't forget it because their coins are in that
transaction. Task 1 (don't let the funder time out after a restart) was done
in #514 (2018). Task 2 (get the funder's money back) is still not done on
master: lnd never gives up on an unconfirmed funding tx it initiated, never
notices when the funding inputs get double-spent, and doesn't unlock the
coins. Every PR that tried this was closed unmerged. Today recovery is
manual only.

## Evidence
- Task 1 done: #514 merged; Roasbeef 2018-02-27 "First portion fixed by #514".
- Task 2 still open on master `0c538e1f2`:
  - `funding/manager.go:3154`, `waitForFundingWithTimeout`: the timeout
    goroutine only starts when `!ch.IsInitiator && !ch.IsZeroConf()`. The
    funder waits forever, with no timeout, no recovery and no coin unlock.
  - `funding/manager.go` broadcast path: on `PublishTransaction` failure it
    only logs and keeps watching, with the TODO still there:
    `// TODO(halseth): retry more often? Handle with CPFP? Just delete from the DB?`
  - The funding manager has no conflict or double-spend handling (grep for
    `conflict`/`double spend` in `funding/manager.go` returns nothing).
- Agreed design direction (halseth 2019-11-05, from #3149): no new persistent
  funding state. Instead (1) unlock coins after a timeout and (2) detect
  double spends (#1755) to fail the channel gracefully. Neither has landed.
- PR history, all unmerged:
  - #3149 "Funding TX Recovery": closed 2019.
  - #1755 "[WIP] Funding detect double spends": closed 2021.
  - #5567 "Funding detect double spends": closed 2022.
  - #7036 "funding: forget funding tx if conflict tx confirms" (Crypt-iQ):
    closed for inactivity by litbot in Jan 2024.
  - #6400 "[WIP] funding: add publisher" (ellemouton): still open, idle since
    Aug 2023. Roasbeef reopened it as related to #7868.
- Related open bug #7868 (2023), "failed funding broadcast doesn't remove
  pending channels and unlock UTXOs": the double-spend sub-case of this
  issue, with a concrete repro. Narrower, not a full duplicate.
- Manual tools that exist today (from release notes; not tested here as a
  recovery recipe):
  - `lncli abandonchannel` in regular builds (v0.13.1, #5335).
  - `lncli wallet removetx` / `WalletKit.RemoveTransaction` (v0.18.0, #7800):
    removes an unconfirmed tx from the wallet.
  - `lncli wallet releaseoutput` to unlock leased UTXOs.
  - `lncli wallet bumpfee` (CPFP on the change output) to get the tx
    confirmed.
- No newer open issue duplicates the whole scope (title searches for
  unconfirmed/stuck/double-spend/cancel funding found nothing open beyond
  #7868).
