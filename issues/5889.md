## Summary
Request (Oct 2021): harden lnd's GitHub Actions setup. The reporter's point
(the title means "are *not* getting updated") is that lnd uses its own frozen
copies of some third-party actions, which never receive upstream security
fixes, and asks for three things: stop using frozen copies, pin every action
to an exact commit, and declare minimal permissions per workflow. A maintainer
agreed with two of the three in 2021. On master the permissions part is mostly
done, but the copies used for the Docker image build are still from January
2021 and most actions are still referenced by a movable version tag.

## Evidence
- Thread: guggero (MEMBER), 2021-10-25: "I think we should indeed move to
  specific pinned versions by specifying the full SHA. And defining
  permissions sounds good to me too. But for now I think it's better to have
  the actions vendored as that specific version was reviewed explicitly." The
  reporter's follow-up question, how security issues in the vendored version
  get mitigated, was never answered. No cross-referenced PRs.
- Background: vendoring was introduced by #4952 (guggero, merged 2021-01-28)
  so that steps touching secrets such as Docker Hub credentials do not depend
  on third-party action repositories. The copies live in
  `lightninglabs/gh-actions`.
- Ask 1, vendored copies going stale. Still true for the Docker build:
  `.github/workflows/docker.yml:44-68` uses `setup-qemu-action`,
  `setup-buildx-action`, `login-action` and `build-push-action` from
  `lightninglabs/gh-actions@2021.01.25.00`. That repo has had one update since
  January 2021 (2024-07-23, `c7149b6a7` "action-gh-release: bump to v2.0.8"),
  which only touched the release action. The login step receives the Docker
  Hub credentials.
- Ask 2, pin by commit. Partly done: of 54 references to external actions on
  master, 5 are pinned to a full commit SHA (`action-gh-release` in
  `release.yaml:46`, `gateway-action`, `backport-action`, and
  `claude-code-action` in two workflows) and 49 use a tag, including
  `actions/checkout@v4`/`v5`, `coverallsapp/github-action@v2`,
  `satackey/action-docker-layer-caching@v0.0.11`,
  `flowwer-dev/pull-request-stats@v2.11.0`, `anthropics/claude-code-action@v1`
  (`claude.yml:47`) and the four vendored Docker actions above. At the time of
  the issue, `release.yaml:43` used the vendored release action by tag; that
  one is now SHA-pinned.
- Ask 3, permissions. Mostly done: 10 of 12 workflow files declare a
  `permissions:` block (for example `main.yml:19` with `contents: read`). The
  two without one are `release.yaml` and `docker.yml`, the workflows that
  publish release files and Docker images.
- Automatic update monitoring: no `.github/dependabot.yml`. The reporter's
  related issue #5740 (Dependabot) was closed 2026-02-21 as a duplicate of
  #5944 "LND External dependency policy", which is open.
- No newer issue or PR found for pinning actions, workflow permissions or
  vendored actions.
- No reproduction: this is a configuration review, checked by reading
  `.github/` on master.

## Assessment for the human
The gap is real and the maintainer agreed with pinning and permissions, so
this is not a candidate for closing as fixed or not planned. Product
questions:
1. Vendoring policy. guggero wanted to keep vendored copies in 2021; the
   reporter wanted them gone. In practice the copies were refreshed once in
   five years. Either someone owns refreshing them, or lnd switches to
   upstream actions pinned by commit with automated update PRs. This needs a
   maintainer decision before anyone can do the work.
2. Tracking. The title is confusing and the thread is a 2021 debate. Options
   are to retitle this issue with a short checklist of what remains, or to
   open a fresh, scoped issue and close this one in its favour.
3. Priority and owner. It is labelled `security` and `supply chain` but has
   no priority label and no assignee. The remaining items are small and
   mechanical once question 1 is settled.
4. Relation to #5944. Automated monitoring of action versions could be folded
   into that dependency policy issue, or kept here.

Remaining work, if kept open:
- Refresh or replace the four vendored Docker actions used in `docker.yml`.
- Pin the 49 tag-referenced external actions to commit SHAs.
- Add `permissions:` blocks to `release.yaml` and `docker.yml`.
- Decide on automated update monitoring for actions.
