## Summary
`lncli updatechanpolicy --help` still prints `(default: 0)` for `time_lock_delta`
(and `base_fee_msat`, `fee_rate_ppm`), while the command actually requires all
three to be passed and rejects a delta of 0. Nothing has changed on master since
the 2018 report; five PRs tried to fix it and none merged.

## Evidence
- Built `lncli` from master `32b6e2dce` and ran `updatechanpolicy --help`:
  ```
  --base_fee_msat value    the base fee in milli-satoshis ... (default: 0)
  --fee_rate_ppm value     the fee rate ppm ... (default: 0)
  --time_lock_delta value  the CLTV delta that will be applied to all forwarded HTLCs (default: 0)
  ```
- Cause: flags are `cli.Int64Flag` / `cli.Uint64Flag` under `urfave/cli v1.22.14`
  (`go.mod:57`), which auto-appends the zero-value default to the usage string.
  `cmd/commands/commands.go:2523-2576`.
- The three fields are mandatory: parse logic at `cmd/commands/commands.go:2670-2717`
  returns `base_fee_msat argument missing` / `fee_rate or fee_rate_ppm argument
  missing` / `time_lock_delta argument missing` when any is absent. Confirms
  AndySchroder (2023) and Roasbeef (2024-07-03): "you need to set _all_ the fields".
- Root cause is in the RPC, not the CLI: `PolicyUpdateRequest` uses plain proto3
  scalars for these fields so the server cannot tell "unset" from "0". Only
  `min_htlc_msat` has a `_specified` presence flag (#3697).
- Attempted fixes, all unmerged:
  - #6762 (SachinMeier, 2022) closed by author, no consensus on approach.
  - #6778 (C-Otto, 2022) open, blocked on #6777 (urfave/cli v2 upgrade); overlaps #6762.
  - #8673 (nettijoe96, 2024) open, stalled after review.
  - #10499 (yashbhutwala, Jan 2026) closed for inactivity 2026-04-15.
  - #10500 (yashbhutwala, Jan 2026) closed for inactivity 2026-09-17.
- Latest maintainer direction: yyforyongyu on #10499 (2026-02-11) rejected the
  CLI-only fix and said the proper fix is proto3 `optional` on `base_fee_msat`,
  `fee_rate_ppm`, `time_lock_delta` in `PolicyUpdateRequest`, giving `has_*`
  presence so the server can enforce/omit fields and lncli can use `ctx.IsSet()`.
- #4305 was closed by wpaulino as a duplicate of this issue, so this is the
  canonical tracker. #4155 (fee unit wording) is related but distinct.

## Recommendation
Keep open. The issue is well-labeled (`good first issue`, `documentation`, `P4`)
and there is now an agreed design from a maintainer. A useful edit would be to
add a comment pointing future contributors at yyforyongyu's guidance on #10499
so the sixth attempt does not repeat the first five.

## Draft comment
Not closing this. Keeping it open as the tracker for the misleading `(default: 0)` text in `lncli updatechanpolicy --help`; #4305 was closed as a duplicate of it.

For anyone picking this up: five PRs have tried this (#6762, #6778, #8673, #10499, #10500) and none merged. Four of them changed only the CLI, and that is why they stalled: the problem is in the RPC, not the help text. `PolicyUpdateRequest` cannot tell "field not set" from "field set to 0", so the CLI is forced to require `base_fee_msat`, `fee_rate`/`fee_rate_ppm`, and `time_lock_delta` on every call, and the help text can't honestly describe a default.

@yyforyongyu laid out the agreed approach in https://github.com/lightningnetwork/lnd/pull/10499#issuecomment-3881539876: mark those three fields as proto3 `optional` in `PolicyUpdateRequest`, so the server gets presence (`Has*`) and can update fields independently, then have lncli use `ctx.IsSet()` to only send what the user passed. `min_htlc_msat_specified` (#3697) shows the older pattern for the same idea. A new PR that starts from that design rather than reworking the flags will have a much easier review.
