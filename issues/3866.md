## Summary
Feature request (Dec 2019, lnd v0.8.2) for an lncli flag to set the invoice's
final CLTV expiry delta, which the gRPC AddInvoice already supported. Shipped
in lnd v0.18.3 by PR #8491 as `lncli addinvoice --cltv_expiry_delta`.

## Evidence
- PR #8491 "Expose `cltv_expiry` flag of `addinvoice` to cli" by davidgumberg,
  merged 2024-06-04, merge commit `a832371d6`. Listed in
  `docs/release-notes/release-notes-0.18.3.md:138`.
- On current master `cmd/commands/cmd_invoice.go:66` defines the
  `cltv_expiry_delta` flag on `addinvoice` and `:191` passes it into the
  request's `CltvExpiry` field. PR #8491 also added it to `addholdinvoice`.
- Flag name differs from the issue title (`cltv_expiry_delta`, not
  `cltv-expiry`); same functionality.
- Two earlier attempts, PRs #6086 and #7299, were closed without merging in
  favour of later work. Neither is needed for the verdict.
- Issue has zero comments and carries `good first issue`; the label should
  come off when it is closed.

## Draft comment
Closing this, because the option was added in lnd v0.18.3 by #8491. You can
now run `lncli addinvoice --cltv_expiry_delta <blocks>` to set the final
timelock delta on the invoice, and the same flag works for `addholdinvoice`.
The flag is named `cltv_expiry_delta` rather than `cltv-expiry`, but it does
what this request asked for.
