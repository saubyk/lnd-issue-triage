## Summary
Request (Apr 2020, lnd v0.10 era, no comments since): let a PSBT-funded channel
open spend an output that needs a preimage (an HTLC sweep) by having lnd read
the preimage from a custom PSBT field. No such field was added, but the goal is
reachable without it. The caller can build the final witness itself and hand
lnd either a PSBT that already carries it or, since v0.12.0, the final raw
transaction. Both were confirmed on master with a real preimage spend. What is
left is a product call: whether lnd should also learn to assemble such a
witness itself.

## Evidence
- Thread: zero comments, zero cross-references, last updated 2020-04-06.
  Labels `enhancement`, `wallet`, `psbt`. No duplicate found ("psbt preimage").
- Raw transaction path: PR #4601 "PSBT funding: allow final TX to be specified
  as raw wire format transaction", merged 2020-09-15, milestone 0.12.0. Adds
  `final_raw_tx` to `FundingPsbtFinalize` (`lnrpc/lightning.proto:2671`), and
  `lncli openchannel --psbt` accepts a hex raw transaction at the last step.
  `final_raw_tx` is absent from the proto at v0.11.0-beta and present at
  v0.12.0-beta.
- `lnwallet/chanfunding/psbt_assembler.go:344` `FinalizeRawTX` only checks
  that outputs and input outpoints match the verified PSBT and that every
  input has a non-empty witness or signature script (`:377`). It does not care
  what kind of script is being spent.
- Finalized PSBT path: `Finalize` (`:316`) calls `psbt.MaybeFinalizeAll`
  (`:327`). btcd's `psbt/v2@v2.0.0/finalizer.go:170` skips any input that
  already has `FinalScriptWitness` set, so an input finalized by the caller
  passes through untouched. `MaybeFinalizeAll` was already called at
  v0.10.0-beta; whether the older library skipped pre-finalized inputs was not
  checked.
- The gap the issue describes is real: a PSBT with only the signature and
  witness script for a hash-locked output is rejected with "Unsupported script
  type", because btcd's finalizer only knows standard script types.
- The PSBT standard has since gained its own preimage fields
  (`PSBT_IN_RIPEMD160` 0x0a, `PSBT_IN_SHA256` 0x0b, `PSBT_IN_HASH160` 0x0c,
  `PSBT_IN_HASH256` 0x0d in BIP 174), so a custom lnd tag would no longer be
  the right design. btcd's psbt package (v2.0.0) does not parse those fields
  and has no miniscript-aware finalizer.
- The verify step requires all inputs to be SegWit
  (`psbt_assembler.go:286`), which a P2WSH HTLC output satisfies.

```go
package chanfunding

import (
	"bytes"
	"crypto/sha256"
	"testing"

	"github.com/btcsuite/btcd/btcec/v2"
	"github.com/btcsuite/btcd/psbt/v2"
	"github.com/btcsuite/btcd/txscript/v2"
	"github.com/btcsuite/btcd/wire/v2"
	"github.com/lightningnetwork/lnd/input"
	"github.com/lightningnetwork/lnd/keychain"
	"github.com/stretchr/testify/require"
)

// issue4159Setup returns a PSBT intent in the verified state whose funding
// transaction spends a single hash-locked P2WSH output (OP_SHA256 <hash>
// OP_EQUALVERIFY <key> OP_CHECKSIG), together with the fully valid witness
// stack (signature, preimage, script) that spends it.
func issue4159Setup(t *testing.T) (*PsbtIntent, *psbt.Packet, wire.TxWitness) {
	a := NewPsbtAssembler(chanCapacity, nil, &params, true)
	intent, err := a.ProvisionChannel(&Request{LocalAmt: chanCapacity})
	require.NoError(t, err)
	psbtIntent := intent.(*PsbtIntent)

	_, localPubkey := btcec.PrivKeyFromBytes(localPrivkey)
	_, remotePubkey := btcec.PrivKeyFromBytes(remotePrivkey)
	psbtIntent.BindKeys(
		&keychain.KeyDescriptor{PubKey: localPubkey}, remotePubkey,
	)
	_, _, packet, err := psbtIntent.FundingParams()
	require.NoError(t, err)

	// The hash-locked output we are sweeping into the channel.
	htlcKey, htlcPub := btcec.PrivKeyFromBytes([]byte{7, 7, 7})
	preimage := bytes.Repeat([]byte{0x42}, 32)
	hash := sha256.Sum256(preimage)

	builder := txscript.NewScriptBuilder()
	builder.AddOp(txscript.OP_SHA256)
	builder.AddData(hash[:])
	builder.AddOp(txscript.OP_EQUALVERIFY)
	builder.AddData(htlcPub.SerializeCompressed())
	builder.AddOp(txscript.OP_CHECKSIG)
	htlcScript, err := builder.Script()
	require.NoError(t, err)

	htlcPkScript, err := input.WitnessScriptHash(htlcScript)
	require.NoError(t, err)
	utxo := &wire.TxOut{
		Value:    int64(chanCapacity) + 1000,
		PkScript: htlcPkScript,
	}

	packet.UnsignedTx.TxIn = []*wire.TxIn{{
		PreviousOutPoint: wire.OutPoint{Hash: [32]byte{1}, Index: 0},
	}}
	packet.Inputs = []psbt.PInput{{
		WitnessUtxo:   utxo,
		WitnessScript: htlcScript,
	}}

	require.NoError(t, psbtIntent.Verify(packet, false))
	require.Equal(t, PsbtVerified, psbtIntent.State)

	// Sign the spend outside of lnd, as the external wallet would.
	fetcher := txscript.NewCannedPrevOutputFetcher(
		utxo.PkScript, utxo.Value,
	)
	sigHashes := txscript.NewTxSigHashes(packet.UnsignedTx, fetcher)
	sig, err := txscript.RawTxInWitnessSignature(
		packet.UnsignedTx, sigHashes, 0, utxo.Value, htlcScript,
		txscript.SigHashAll, htlcKey,
	)
	require.NoError(t, err)
	witness := wire.TxWitness{sig, preimage, htlcScript}

	// Sanity: the witness really is a valid spend of the output.
	signedTx := packet.UnsignedTx.Copy()
	signedTx.TxIn[0].Witness = witness
	vm, err := txscript.NewEngine(
		utxo.PkScript, signedTx, 0, txscript.StandardVerifyFlags, nil,
		txscript.NewTxSigHashes(signedTx, fetcher), utxo.Value, fetcher,
	)
	require.NoError(t, err)
	require.NoError(t, vm.Execute(), "preimage spend must be valid")

	packet.Inputs[0].PartialSigs = []*psbt.PartialSig{{
		PubKey:    htlcPub.SerializeCompressed(),
		Signature: sig,
	}}

	return psbtIntent, packet, witness
}

func serializeWitness(t *testing.T, witness wire.TxWitness) []byte {
	var buf bytes.Buffer
	require.NoError(t, wire.WriteVarInt(&buf, 0, uint64(len(witness))))
	for _, item := range witness {
		require.NoError(t, wire.WriteVarBytes(&buf, 0, item))
	}

	return buf.Bytes()
}

// roundTrip encodes and decodes the packet as it would travel over the RPC.
func roundTrip(t *testing.T, packet *psbt.Packet) *psbt.Packet {
	var buf bytes.Buffer
	require.NoError(t, packet.Serialize(&buf))
	decoded, err := psbt.NewFromRawBytes(&buf, false)
	require.NoError(t, err)

	return decoded
}

// Path 1: the caller finalizes the preimage input itself and hands lnd a PSBT
// that carries the final witness.
func TestIssue4159FinalizedPsbt(t *testing.T) {
	intent, packet, witness := issue4159Setup(t)

	packet.Inputs[0].PartialSigs = nil
	packet.Inputs[0].WitnessScript = nil
	packet.Inputs[0].FinalScriptWitness = serializeWitness(t, witness)

	require.NoError(t, intent.Finalize(roundTrip(t, packet)))
	require.Equal(t, PsbtFinalized, intent.State)

	tx, err := intent.CompileFundingTx()
	require.NoError(t, err)
	require.Equal(t, witness, tx.TxIn[0].Witness)
	t.Logf("accepted, funding txid %v, witness items %d", tx.TxHash(),
		len(tx.TxIn[0].Witness))
}

// Path 2: the caller hands lnd the final raw transaction.
func TestIssue4159RawTx(t *testing.T) {
	intent, packet, witness := issue4159Setup(t)

	rawTx := packet.UnsignedTx.Copy()
	rawTx.TxIn[0].Witness = witness

	require.NoError(t, intent.FinalizeRawTX(rawTx))
	require.Equal(t, PsbtFinalized, intent.State)

	tx, err := intent.CompileFundingTx()
	require.NoError(t, err)
	require.Equal(t, witness, tx.TxIn[0].Witness)
	t.Logf("accepted, funding txid %v, witness items %d", tx.TxHash(),
		len(tx.TxIn[0].Witness))
}

// The gap the issue describes: a PSBT with only the signature and script (no
// place for the preimage) cannot be turned into a valid spend by lnd.
func TestIssue4159UnfinalizedPsbt(t *testing.T) {
	intent, packet, witness := issue4159Setup(t)

	err := intent.Finalize(roundTrip(t, packet))
	if err != nil {
		t.Logf("rejected: %v", err)
		return
	}

	tx, err := intent.CompileFundingTx()
	require.NoError(t, err)
	require.NotEqual(t, witness, tx.TxIn[0].Witness)

	utxo := packet.Inputs[0].WitnessUtxo
	fetcher := txscript.NewCannedPrevOutputFetcher(
		utxo.PkScript, utxo.Value,
	)
	vm, err := txscript.NewEngine(
		utxo.PkScript, tx, 0, txscript.StandardVerifyFlags, nil,
		txscript.NewTxSigHashes(tx, fetcher), utxo.Value, fetcher,
	)
	require.NoError(t, err)
	err = vm.Execute()
	require.Error(t, err)
	t.Logf("accepted by lnd with %d witness items (no preimage); "+
		"script engine says: %v", len(tx.TxIn[0].Witness), err)
}
```

## Assessment for the human
The reporter's goal, funding a channel straight from an HTLC sweep, works
today as long as the application that knows the script builds the final
witness. lnd cannot do that step itself and nobody has asked for it again in
six years. Options:
1. Close as not planned (recommended; draft below). The witness for a custom
   script is the caller's job, lnd accepts the result, and a custom lnd-only
   PSBT tag is the wrong design now that BIP 174 has standard preimage fields.
   Same shape as #3971.
2. Keep open as a narrower request: support the standard BIP 174 preimage
   fields and a script-aware finalizer. That work would land in btcd's psbt
   package first, not in lnd.

## Decision
Closed as not planned on 2026-09-30: the caller finalizes the preimage input
(finalized PSBT or `final_raw_tx`); added script-handling complexity in the
safety-critical funding path is not justified for a non-critical feature.

## Draft comment
Closing this as not planned. The application that knows the HTLC script can already build the final witness, preimage included, and lnd will accept the result: at the last step of a PSBT channel open you can pass either a PSBT in which that input is already finalized, or the fully signed raw transaction (available since v0.12.0, #4601). Teaching lnd to read a preimage from the PSBT and assemble that spend itself would add script-handling logic to the channel funding path, which is safety-critical code we would then have to maintain. Since the same outcome is reachable today, we don't think that extra complexity is justified for the benefit. The PSBT standard has also since added its own preimage fields, so an lnd-specific tag would no longer be the right place for this.
