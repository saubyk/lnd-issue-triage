## Summary
Docs request (Jun 2020, lnd v0.10.1) from a now-deleted account: the public
API reference tracked master, so it showed fields that were not in the latest
release. Reporter wanted it pinned to releases, or a per-version dropdown.
In-thread, wpaulino (then a maintainer) said master tracking should stay and
per-version docs "should definitely" be added. Six years on, the docs site
still builds from master daily and has no version selector. The docs are
generated by a separate repo, lightninglabs/lightning-api-ng, not by lnd.
Product call: close in lnd as out of scope (the page now states the commit it
was built from, and per-release protos are on GitHub), or move the ask to the
docs repo.

## Evidence
- Old URL api.lightning.community now redirects to
  https://lightning.engineering/api-docs/api/lnd.
- Generator: https://github.com/lightninglabs/lightning-api-ng. README says
  the pipeline "downloads the master branch of each repo" and runs "every day
  at midnight UTC". `generate.sh` defaults `LND_COMMIT` to `master`; a commit
  can be overridden per build but nothing publishes multiple versions.
- Live page HTML is Docusaurus with `docusaurus_version` = `current` only;
  no versioned docs plugin in use. The page does display the lnd commit it
  was generated against.
- Nothing in the lnd repo itself drives the docs build (`grep` of
  `.github/`, `Makefile`, `docs/` finds only an inbound link). Any change
  would land in lightning-api-ng, not lnd.
- No duplicate issue in lnd; not checked in lightning-api-ng.

## Decision needed
1. Close in lnd as not planned here. The docs site is owned by a different
   repo, it states the commit it was built from, and the exact API for any
   release is the `.proto` files at that release tag on GitHub. Draft below.
2. Close here and re-file in lightninglabs/lightning-api-ng as "publish
   per-version docs", since a maintainer endorsed the idea in 2020. If you
   want this, say so and I will draft the new issue text for you to post.

## Draft comment (only if you choose option 1)
Closing this as not planned in lnd, because the API reference site is built
by a separate project, not by this repository. The site now shows the exact
lnd commit each page was generated from, so you can tell when a field is
newer than the release you are running. For the API of a specific release,
the definitive reference is the `.proto` files at that release's tag on
GitHub, for example `lnrpc/lightning.proto` under the v0.19.x tag. If
per-version pages on the docs site would help you, the place to request that
is the lightninglabs/lightning-api-ng repository.
