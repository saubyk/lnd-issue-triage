## Summary
Feature request (Jan 2020) from hsjoberg (Blixt wallet) for a `QueryRouteHints`
RPC that returns the route hints for the node's own private channels, so a
keysend sender can be given them without creating a throwaway invoice. No such
RPC exists on current master. The workaround joostjager proposed in-thread
(ListChannels + GetChanInfo) still works, and its one known gap with SCID
aliases was closed in v0.16.1. This is a product call: add a convenience RPC,
or close as "workaround is sufficient".

## Evidence
- No `QueryRouteHints` or equivalent in `lnrpc/lightning.proto`,
  `routerrpc/router.proto`, or `invoicesrpc/invoices.proto`. The hop-hint
  selection logic exists only as an internal helper used by AddInvoice
  (`lnrpc/invoicesrpc/addinvoice.go`, `PopulateHopHints`, `selectHopHints`).
- Workaround still valid: `ListChannels` gives the private channels;
  `GetChanInfo` gives the peer's routing policy (fees, CLTV delta).
- The 2023 comment by djkazic reported that the workaround breaks for
  zero-conf / option_scid_alias channels because `listchannels` showed our
  alias, not the peer's. PR #7366 added `peer_scid_alias` to `ListChannels`
  (released in v0.16.1; `lnrpc/lightning.proto:1578`), which is the value a
  route hint needs. So the workaround is complete again.
- joostjager (then a maintainer) said in-thread that a dedicated RPC "may
  eventually be superseded by an rpc call that generates a complete keysend
  bolt11 invoice". That never landed either. Nobody declined the request.
- Cross-refs #1480 and #6601 are closed and do not track this ask. No
  duplicate open issue found.
- Caveat: the `lnd/` worktree is a shallow clone (21k commits, no full
  history), so `git log -S` searches are unreliable. PR and release
  attribution above came from release notes and the GitHub API instead.

## Decision needed
Does lnd want a convenience RPC for "route hints to me"? Options:
1. Close as not planned: the workaround (ListChannels + GetChanInfo, using
   `peer_scid_alias`) covers the need, and blinded paths are the direction
   for private receiving now. A draft for this option is below.
2. Keep open as a low-priority enhancement and leave it to a contributor.
   hsjoberg offered to implement in 2020; that offer is six years old.

## Draft comment (only if you choose option 1)
Closing this as not planned, because the need it describes can be met with
existing RPCs and there is no plan to add a dedicated one. To build route
hints for your own private channels, list them with `ListChannels` and read
each peer's fee and timelock policy from `GetChanInfo`. The problem with
alias channels raised in 2023 was fixed in v0.16.1 (#7366), which added the
`peer_scid_alias` field to `ListChannels` so you get the alias the peer
expects. If a dedicated RPC would still materially help your wallet, please
open a new issue with the concrete use case.
